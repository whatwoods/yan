# 砚 · 产品愿景与技术设计

_Spec written 2026-05-03 · 为「砚」PWA 的完整 v1.0 愿景_

---

## 1. 一句话

**「砚」是一本会思考的笔记本——记下即整理，不再让你管标签、文件夹、关联。**

---

## 2. 目标用户

「想随手记又懒得整理」的普通中文用户。

不是知识工作者的精密工具，不是研究者的二脑，不是创作者的素材库。砚的用户每天写下三五条想法、几段聊天回顾、一两条待办，希望系统替自己把它们放对地方。

竞品意识：Apple Notes（太被动）、Flomo（要手填标签）、即刻（不私密）、Heptabase（太重）。

---

## 3. 三条核心原则

每个功能取舍都受这三条约束。

### 3.1 不打扰原则
砚永远不弹窗、不打断、不主动通知。AI 在后台跑，识别完静悄悄出现；月度小结不推送、安静地放在「砚」页等被读；整理建议同理。做错了用户改一次，砚记住偏好——但绝不主动询问。

### 3.2 零摩擦捕获
从「想记」到「开始记」不超过 1 秒。任何让用户停下来想「这个该归哪类」的设计都是失败。AI 在保存后接手所有整理工作。

### 3.3 数据是你的
笔记以 Markdown 文件存于用户自己的 WebDAV，可被 Obsidian 等工具读，导出离开零障碍。砚是个有意见的查阅器，不是数据牢笼。

**对应隐私承诺：** 砚不上报任何 telemetry / analytics / 崩溃数据。所有数据流向只有用户自己的 WebDAV 和用户自己的 AI 供应商。

---

## 4. 商业意图

个人作品 / 自用为主。不商业化，不组团队，不追增长。开源与否暂未决定。迭代节奏由作者节奏决定，可以慢，但要做到日用品级别。

---

## 5. 架构总览

```
┌────────────────────────────────────────────────┐
│  PWA 客户端（手机 / 桌面 共用同一份代码）       │
│  ┌──────────────────────────────────────────┐  │
│  │  UI（React，纸质感设计系统）              │  │
│  ├──────────────────────────────────────────┤  │
│  │  笔记仓库（IndexedDB · 本地真相）         │  │
│  ├──────────────────────────────────────────┤  │
│  │  同步引擎（WebDAV 适配器）                │  │
│  ├──────────────────────────────────────────┤  │
│  │  AI 服务（OpenAI 兼容协议 · BYOK）        │  │
│  └──────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
         │                          │
         ↓                          ↓
   用户的 WebDAV              用户的 AI 供应商
   (.md + 附件 + 加密 Key)   (魔搭/小米/DeepSeek/...)
```

**关键属性：**
- 无后端服务器（作者不维护、不掏钱、不背风险）
- 客户端是纯 PWA，桌面也走浏览器
- 离线完全可用，AI 调用失败时降级到规则版
- 数据流向只有两个出口：用户的 WebDAV、用户的 AI 供应商

## 6. 数据模型

### 6.1 笔记格式

每条笔记 = 一个 `.md` 文件。frontmatter 是元数据，正文是 Markdown。

```markdown
---
id: 2026-05-03-1742-a3f
created: 2026-05-03T17:42:13+08:00
modified: 2026-05-03T17:43:01+08:00
kind: text                       # text | voice | photo | mixed
category: 工作                   # 大分类，恰好一个（见 §10）
tags: [产品, 首屏, 决策]         # 小标签，零到 N 个
people: [阿宁]                   # AI 抽取的人物
pinned: false
ai:
  summary: 建议把输入框作为视觉中心…
  generated_at: 2026-05-03T17:42:18+08:00
  model: deepseek-chat           # 用了哪个模型生成的
attachments:
  - photo-1.jpg                  # 仅照片，无音频
---

晚饭后又重新想了一遍首屏…（Markdown 正文）
```

**ID 格式：** `YYYY-MM-DD-HHMM-<3字符设备指纹>`，时间排序友好、设备区分、避免冲突。

**附件：** 仅照片支持。语音笔记只存转写文本，不留音频文件——失去音色但换来体积轻、纯文本可被任何工具读。

### 6.2 WebDAV 目录布局

按年月 sharding，避免单目录文件过多。

```
/biji/
├── notes/
│   ├── 2026/
│   │   ├── 05/
│   │   │   ├── 03-1742-a3f.md
│   │   │   └── 03-1808-b2e.md
│   │   └── 04/...
│   └── 2025/...
├── attachments/
│   └── 2026-05-03-1742-a3f/
│       └── photo-1.jpg
├── trash/                       # 软删除回收站，30 天
│   └── 2026-04-15-...md
├── conflicts/                   # 同步冲突另存
│   └── <id>.<device>.md
├── categories.json              # 大分类列表（同步）
├── insights/                    # 月度洞察
│   └── 2026-05.md
├── secrets.enc                  # 加密的 API Keys
├── preferences.md               # 用户偏好（如打标签倾向）
└── curator-rejected.md          # 已拒绝的 Curator 提议
```

**默认只扫近 6 个月** notes，点「更早」按需加载历史月份。

### 6.3 本地索引

**不写盘。** 启动时扫描近 6 个月的 `.md` 文件构建内存索引（数百条 ms 级），按需扩展更早。损坏 = 重启重建，永不丢数据。

索引内容：`{id, title, category, tags, people, created, modified, kind, summary, pinned}` 摘要——足以驱动列表、筛选、洞察、Curator。问砚需要正文时按 id 实时读取 `.md`。

## 7. 同步与冲突

WebDAV 是简单的文件系统协议，没有 git 那种合并机制。砚的策略是**保守 + 可解释**。

### 7.1 同步触发
- 应用启动时
- 网络恢复时
- 写入新笔记或修改后 5 秒（防抖）
- 用户手动「下拉同步」

### 7.2 冲突处理

| 情况 | 处理 |
|---|---|
| **新建笔记** | 不会冲突——id 内含设备指纹 |
| **同设备双端编辑** | 后写覆盖（modified 时间戳判断） |
| **真冲突**（A、B 设备都改了同一笔记） | 不合并，**两份都留**：原文件 + `/biji/conflicts/<id>.<device>.md`。砚在「本」页顶部安静地告诉你「有 1 条冲突待你处理」，点开是并排 diff，你选保留哪份 |

不引入 CRDT 或自动合并——增加复杂度但用户感觉不到收益。

## 8. AI 架构（BYOK · 多供应商）

### 8.1 协议

**OpenAI 兼容协议**——所有调用都走 `/v1/chat/completions` 与 `/v1/models`。不引入特定 SDK，原生 fetch 直发。

### 8.2 预设供应商

| 供应商 | endpoint | 备注 |
|---|---|---|
| **魔搭 ModelScope** | `https://api-inference.modelscope.cn/v1` | **默认推荐 · 国内首选** |
| DeepSeek | `https://api.deepseek.com/v1` | 性价比之王 |
| Moonshot Kimi | `https://api.moonshot.cn/v1` | 长上下文友好 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | OpenAI 兼容模式 |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 阿里 |
| MiniMax | `https://api.minimax.chat/v1` | |
| 小米 | `https://token-plan-cn.xiaomimimo.com/v1` | |
| OpenRouter | `https://openrouter.ai/api/v1` | 一个 Key 打全场 |
| OpenAI | `https://api.openai.com/v1` | |
| **自定义** | 用户填 base URL + Key | 任何 OpenAI 兼容端点 |

### 8.3 模型管理

- 用户填完 Key 后自动 `GET /v1/models` 拉模型列表
- 列表带搜索框（百来个模型时常需要找）
- 拉不到就降级到手填 model id
- **支持任务级模型分配**——不同任务用不同模型：

| 任务 | 推荐模型档位 | 触发频率 |
|---|---|---|
| 自动分类 | 便宜小模型（Qwen-Turbo / DeepSeek-Chat） | 每条笔记 |
| 自动标签 + 摘要 | 便宜小模型 | 每条笔记 |
| 月度洞察 | 中档（Sonnet / DeepSeek-V3 / GLM-4） | 每月 1 次 |
| 问砚（RAG） | 强模型（DeepSeek-R1 / Sonnet / Qwen-Max） | 用户主动 |
| 整理建议 (Curator) | 强模型 | 每周 1 次 |

UI 上：「设置 · 砚」里每个任务一行下拉，可选当前已配置 Key 下的任意模型。

### 8.4 调用时机（严格服从「不打扰」）

| 任务 | 触发 | 失败行为 |
|---|---|---|
| 分类 + 标签 + 摘要 | 保存后 1.5 秒（防抖） | 静默用规则版兜底，不打扰 |
| 月度洞察 | 每月 1 号空闲时跑一次 | 保留上月版本 + 「砚」页底部小字「上次跑洞察失败，可点重试」 |
| 问砚 | 用户主动 | 弹一行红色提示「砚此刻没法应答 · 检查 Key 或网络」 |
| Curator | 每周日早晨空闲时 | 完全静默，下周再试 |

### 8.5 Key 加密与同步

```
首次启动 → 设主密码（≥8 位）
        → PBKDF2(密码, 设备指纹盐, 600k 轮) → 主密钥 K
        → 用 K 加密所有 API Keys，AES-GCM
        → 加密 blob 存 /biji/secrets.enc
新设备 → 拉到 secrets.enc → 让用户输主密码 → 解开 → 全部 Key 就位
```

**忘记主密码 = Key 失效**，需重填。笔记本身不加密——v1 假设 WebDAV 是用户自己的或可信的。

### 8.6 设置项的同步范围

| 设置 | 同步 | 说明 |
|---|---|---|
| API Keys（加密后） | ✅ | `/biji/secrets.enc` |
| 主密码 | ❌ | 仅在设备记忆中，每次启动需输入 |
| WebDAV 凭据 | ❌ | 每台设备各填，太敏感不放云 |
| 大分类列表（含色彩） | ✅ | `/biji/categories.json` |
| 字体 / 密度 / 砚的人格 | ❌ | 每台设备口味不同 |
| 任务级模型分配 | ✅ | 在 secrets.enc 同一文件内 |
| 拒绝过的 Curator 提议 | ✅ | `/biji/curator-rejected.md` |
| 月度洞察（生成结果） | ✅ | `/biji/insights/<year>-<month>.md` |
| 用户偏好（打标签倾向） | ✅ | `/biji/preferences.md` |

## 9. 问砚（RAG · Tier 1）

砚的查询特点：~70% 是「时间 + 主题」型，~20% 是「模糊回想」型，~10% 是「关联型」。语料规模天然有限（500–2000 条），不需要重型向量基建。

### 9.1 Tier 1 流程（v1 默认）

1. 用户问：「上个月关于产品的想法」
2. 砚调一次便宜小模型做查询解析：
   ```json
   { "time_range": "2026-04", "categories": ["工作"], "tags": ["产品"], "people": [], "free_text": "想法" }
   ```
3. 在内存索引按结构化条件过滤 → 候选 ~30 条
4. 候选笔记的 `{title, summary, tags}` + 用户原问句 → 喂给主强模型 → 砚回答 + 引用

**两次 LLM 调用：** 解析（极便宜，~100 token in/out）+ 回答（按候选规模，~3-5k token in）。

### 9.2 解析失败时的降级

LLM 解析返回非法 JSON 或失败 → 降级为「按时间倒排取前 50 条」+ 主模型——仍能答，只是召回粗一点。

### 9.3 Tier 2 / Tier 3（v1 不做，留接口）

- Tier 2（500–2000 条）：加 minisearch BM25 作为第二路召回，与元数据过滤并行后合并
- Tier 3（>2000 条）：加 transformers.js 本地 embedding（bge-small-zh）做重排

v1 一行向量代码不写。

## 10. 大分类 + 标签 · 两层分类法

### 10.1 结构

**大分类（category）·一条笔记一个**
- 默认 7 个，封闭集合（用户可加/改/删）
- 视觉上是「主色调」——卡片左侧一道颜色条
- AI 做的是单选分类，准确率比开放集合高得多

**小标签（tags）·一条笔记多个**
- 完全自由
- AI 抽取，优先复用已有标签
- Curator 在这一层做合并/拆分/新建/归档

### 10.2 默认 7 大分类

| 分类 | 颜色 | 色值 | 寓意 |
|---|---|---|---|
| **学习** | 竹青 | `#5b7a5a` | 生长 |
| **工作** | 群青 | `#3d5a7c` | 庄重 |
| **生活** | 藤黄 | `#c89342` | 温暖 |
| **想法** | 梅紫 | `#8b4a5e` | 闪念 |
| **AI** | 印章红 | `#b8443a` | 砚色 |
| **开发** | 茶色 | `#8b6f47` | 沉静 |
| **收藏** | 墨色 | `#1f1a14` | 沉淀 |

### 10.3 AI 调用拆分

打标签现在是**两次轻量调用**（可并行）：

```
保存后 → 并发：
  1. 分类（封闭集）：从大分类列表里选 1 类  · ~100 token in/out
  2. 抽取（开放集）：tags + people          · 200 token in/out
```

成本基本不变，准确度因为分类被收紧而显著提高。

### 10.4 边界情况

| 情况 | 处理 |
|---|---|
| 笔记跨多类（「跟阿宁聊产品」） | AI 选最强的那个；用户改一次，砚记入偏好 |
| 用户长期写到第 8 类主题 | Curator 在「整理建议」里提议建新分类 |
| 用户删除某分类 | 该分类的笔记 category 字段被清空，下次打标签时 AI 重新分配 |

## 11. Tag Curator · 整理建议

自动打标签系统会随时间漂移变乱（「产品」「产品设计」「PM」分头攒）。Curator 解决这个问题。

### 11.1 触发
- 默认每周一次（周日早晨空闲时）后台跑
- 或新增满 50 条触发
- **永远不打扰**——结果安静地放在「砚」页顶部一行：「砚整理了 4 条建议，看看吗？」

### 11.2 建议类型

| 类型 | 触发条件 | 例 |
|---|---|---|
| **合并** | 两标签共现率高 / 语义相近 | 「`#产品` + `#产品设计` 合并？」 |
| **拆分** | 一标签覆盖太多主题 | 「`#工作`(64) 看起来在讲三件事，要拆吗？」 |
| **新提议** | 反复出现某主题但无标签 | 「最近 11 次写到「杭州行」，单独建？」 |
| **归档** | 长期未用 | 「`#随手` 60 天未用，归档？」 |
| **重命名** | AI 识别出更合适措辞 | 「`#感受` → `#情绪`？」 |
| **新分类** | 用户内容溢出现有 7 类 | 「最近常写「健身」，建新分类？」 |

### 11.3 关键设计取舍

- **永远建议，从不自动执行**——违反「不打扰」否则砚成了独裁者
- **拒绝后不再重复**：被拒提案进 `curator-rejected.md`，下次跳过
- **应用时批量重写**：砚改的是 frontmatter，原文不动；改完显示「已重写 N 条」
- **复用问砚的强模型**——这是高质量推理任务

### 11.4 与自动打标签的关系

- 打标签 = 高频、便宜、即时
- Curator = 低频、稍贵、批量
- Curator 还**反向训练**打标签：合并后未来打标签自动用合并后的名字

## 12. 功能边界

### 12.1 v1 必做（核心三轴）

**轴一：捕获**
- 全能输入框（文字 / 语音转写 / 拍照），三状态切换
- 后台自动保存
- 启动到第一笔 < 1s

**轴二：自整理（核心差异化）**
- 保存后 1.5s 内 AI 分类 + 打标签 + 摘要 + 提取人物
- 标签优先复用已有
- Curator 每周整理建议
- 用户改正一次 = 砚记住偏好

**轴三：取回**
- 时间线翻阅，按 category 顶部 tab，按 tag/people 二级筛选
- 问砚（RAG Tier 1）
- 月度洞察（每月自动生成、安静等被读）

### 12.2 v1 基建

- WebDAV 同步 + 冲突另存
- 多供应商 BYOK + 任务级模型分配
- 主密码同步加密 Keys
- Markdown 导出 / 导入
- PWA 离线可用、可安装
- 软删除回收站（30 天）

### 12.3 v1 不做

- 知识图谱 / 双向链接 / `[[wiki]]` 语法（违背「不打扰」，AI 自动抽取已能覆盖 80%）
- 文档式编辑（块、嵌入、富文本表格）
- 协作 / 分享
- 图片 OCR
- 提醒、待办执行
- 模板系统
- 移动端原生壳（Tauri / Capacitor）
- 向量检索（Tier 3 留接口）
- 端到端笔记加密
- 多语言（中文为主，UI 文案不做 i18n）
- 自动化测试（自用项目，靠手测）
- 键盘快捷键（M3 看情况补）
- PWA 通知 / 角标

### 12.4 灰色地带（v1.x 候选）

- 「砚」每日清晨 / 晚饭后的「待读小簿」（轻提醒，可关）
- 与日历联动
- Obsidian 插件版「砚」（外挂式 AI，不做独立 App）
- Tauri 桌面壳（解决浏览器内存限制）

## 13. 用户流程

### 13.1 冷启动 / 首次使用（半引导式）

1. 欢迎页：一句话「一本会思考的本子」+ 「开始第一笔」按钮
2. 点击进首屏「记一笔」，**立即可写**——AI 未配置时用规则版（关键词标签、字面检索、统计型小结）
3. 顶部一行小字（不打扰）：「砚还没活过来 · 去配 API Key」可点跳设置
4. 设置页四个递进式入口（用户按需配置，无强制顺序）：
   - 配 AI 供应商 + Key + 任务模型 → 砚开始智能识别
   - 配 WebDAV → 笔记开始同步
   - 设主密码 → Key 在多设备间安全同步
   - 改大分类 / 字体 / 砚人格 → 个性化

### 13.2 从原型迁移

启动时检测 localStorage 中的旧数据：
- 自动转换成新 Markdown 格式写入 IndexedDB
- 一次性，迁移完后清掉 localStorage 里的副本
- 用户无感

### 13.3 删除 = 软删除（30 天回收站）

- 删除 = 移到 `/biji/trash/` 并加 `deleted_at` 字段
- 「设置 · 数据 · 回收站」可查看 / 还原 / 永久删除
- 30 天后自动真删（启动时清扫）

### 13.4 语音识别策略

- 默认用浏览器 Web Speech API（zh-CN）
- iOS Safari 不支持 → 改为「录到文件 → 上传 OpenAI 兼容的 Whisper 接口转写」
- 用户配的供应商不提供 Whisper → iOS 上录音按钮灰掉，提示「请用桌面/Android」
- 不强制 Whisper——是可选增强

### 13.5 照片处理

- 上传前压缩到长边 1920px、JPEG q=85
- 单张上限 5MB，超出提示用户裁剪
- 不做 OCR（v1 明确不做）

## 14. 技术栈

### 14.1 构建与语言

**Vite + React 18 + JS（不上 TS）**

- 现代 DX、ES 模块、tree-shaking、热更新
- 自用项目不值 TS 那层税
- 当前原型（Babel standalone）在 M1 重写时换轨

### 14.2 依赖清单

| 用途 | 选型 | 引入时机 |
|---|---|---|
| 视图层 | React 18 | 全期 |
| 状态管理 | React state + Context | 全期 · 不引 Redux/Zustand |
| 路由 | 自写 useRoute hook | 全期 |
| 本地数据库 | IndexedDB · `idb` 包一层 | M1 |
| Markdown 解析 | `gray-matter`（拆 frontmatter） + `marked`（渲染） | M1 |
| YAML | gray-matter 内置 | M1 |
| WebDAV | `webdav` 客户端库 | M1 |
| 加密 | Web Crypto API（浏览器内置） | M1 |

总依赖 6 个 npm 包：`react` · `react-dom` · `idb` · `gray-matter` · `marked` · `webdav` · `minisearch`。生产 bundle 估约 200kb gzipped。

### 14.3 部署

- 静态托管：build 出来 `dist/` 一坨纯静态
- 推荐选项：Cloudflare Pages / Vercel / GitHub Pages / 自托管 nginx
- 域名走 HTTPS（PWA 必需）
- 因为 BYOK + WebDAV，部署后**没有任何后端开销**，永久免费托管可行

### 14.4 开发

- 单目录，不 monorepo
- Git 提交：约定式（feat/fix/chore），不强求
- 不接 CI——本地 build 后手动推
- 版本号：`v0.x` 直到 M3 完成，M3 完成发 `v1.0`

## 16. 成功标准

自用产品没有 DAU / 留存指标，标准就是「我自己愿不愿意每天打开」。

### 16.1 主观标准

1. 一周内用了 ≥ 5 天，无须强迫
2. 砚的标签 ≥ 80% 不需要改
3. 月度洞察读完会想「确实是我」
4. WebDAV 在两台设备间没出过数据丢失

### 16.2 客观可验证

1. 启动到首笔输入 < 1.5s
2. 保存后 AI 标签出现 < 3s（合理 API 延迟下）
3. 1000 条笔记问砚 < 5s 出答案
4. 离线打开能看 / 能写 / 能搜（仅 AI 失效）

| WebDAV 默认扫描范围 | 近 6 个月 |
| 主密码 PBKDF2 轮数 | 600,000 |

### 17.2 AI 失败处理速查

| 任务 | 失败行为 |
|---|---|
| 自动分类 / 标签 / 摘要 | 静默用规则版兜底，不打扰 |
| 月度洞察 | 保留上月版本 +「砚」页底部小字「上次跑洞察失败，可点重试」 |
| 问砚 | 弹一行红色提示「砚此刻没法应答 · 检查 Key 或网络」 |
| Curator | 完全静默，下周再试 |
| WebDAV 同步 | 标记「未同步」状态，恢复网络自动重试，3 次失败提示用户 |
| 主密码错误 | Key 不解密，砚降级为规则版，「砚」页提示「输入主密码可让砚活过来」 |

### 17.3 数据流向（隐私视角）

```
用户输入  →  IndexedDB（本地真相）  →  WebDAV（用户自己的）
                  ↓
             AI 服务（用户自己的供应商，限于内容片段 + 摘要）
```

**永不离开用户控制的两个边界：**
1. WebDAV 服务器 — 用户自管或用户信任的第三方
2. AI 供应商 — 用户自选，可随时换

**砚不上传任何数据到作者的服务器**（作者也没有服务器）。
